# Безопасность

## Границы доверия

Владелец Google Таблицы/Apps Script может прочитать распределение. Приложение не обещает
криптографическую тайну от владельца инфраструктуры. Обычный организатор комнаты не должен
получать полное распределение через будущий API.

Любой открытый RPC доступен напрямую: скрытая кнопка, origin, CORS и приватный репозиторий
не являются авторизацией. Суффикс `_` нужен всем серверным helpers.
В текущем каркасе открыт только диагностический RPC без данных участников.

## До первого реального розыгрыша

- Длинные случайные секреты, серверное хранение хешей, отдельные права организатора и участника.
- Секреты ссылок — во fragment, без query, analytics и referrer; не сохранять в логах.
- Серверная валидация размеров, membership и допустимых переходов состояния.
- Ограничение создания комнат, размера списка, частоты операций и общей нагрузки.
- Авторизация проверяется при каждом запросе; закрытая таблица не публикуется в веб.
- Защита от XSS и formula injection; пользовательские строки выводить через textContent.
- Идемпотентность и блокировки, предсказуемое поведение при сетевом таймауте.
- Удаление данных, ограниченный срок хранения, запрет логирования пожеланий/пар/токенов.

Не размещать Google credentials и OAuth tokens на Pages. В проекте нет сторонних analytics,
шрифтов, CDN или runtime dependencies. Лицензию и политику обработки данных нужно определить
перед публичным запуском. Rate limit приложения не защищает от DDoS и не гарантирует сохранность квот Google.
