# Публикация

1. В существующем проекте Apps Script синхронизируйте все файлы backend/ и манифест appsscript.json. Обновляйте содержимое существующих файлов без создания вторых копий одноимённых функций.
2. В Script Properties сохраните SPREADSHEET_ID закрытой таблицы и SERVICE_ENABLED=true. Лимиты задаются REQUESTS_PER_MINUTE и REQUESTS_PER_DAY. Владелец deployment должен иметь доступ к таблице.
3. Авторизуйте разрешение Sheets для игрового кода и в Manage deployments обновите существующее веб-приложение на новую версию. Сохраните параметры запуска от имени владельца и доступа без входа. Обновление существующего deployment сохраняет /exec URL.
4. В GitHub Settings → Pages укажите GitHub Actions. В Actions variables задайте APPS_SCRIPT_URL с публичным адресом /exec. Для локального запуска значение по умолчанию находится в web/config.js.
5. Отправьте изменения в main. Workflow сначала проверяет и собирает сайт, затем публикует dist/.

## Проверка после публикации

В приватном окне откройте /exec и проверьте диагностику. Затем с Pages создайте тестовую комнату. В двух независимых браузерных профилях вступите по приглашению, добавьте тестовые фото и пожелания, сохраните личные ссылки. Запустите жеребьёвку организатором и откройте личные ссылки повторно. Проверьте, что у каждого один получатель, никто не дарит себе и запись в комнату закрыта.

При откате сайта используйте revert и повторную публикацию. В Apps Script выберите совместимую версию в Manage deployments. При сбое операции с комнатами можно временно выключить через SERVICE_ENABLED.
