# Лимиты и эксплуатация

## Script Properties

| Имя | По умолчанию | Назначение |
| --- | --- | --- |
| SERVICE_ENABLED | false | Только точное true разрешает диагностику и игровые запросы |
| REQUESTS_PER_MINUTE | 30 | Общий лимит успешных допусков в минуту |
| REQUESTS_PER_DAY | 500 | Общий лимит успешных допусков за сутки UTC |
| REQUEST_BUDGET_V1 | автоматически | JSON состояния бюджета; вручную не изменять |

Стартовые лимиты консервативны и не соответствуют напрямую квотам Google.
Это фиксированные окна: на границе минут возможен кратковременный двойной burst.
Бюджет общий для диагностики и игровых операций. Дополнительно допускается до 10 активных комнат и 50 участников в каждой.

## Что лимит не предотвращает

Apps Script уже запускается для проверки бюджета. Отклонённые запросы всё равно расходуют
исполнения, чтения Properties и время. Перезагрузка /exec тоже использует Google инфраструктуру.
Нельзя достоверно узнать единый «остаток всех квот» и гарантировать, что свой бюджет
сработает раньше квоты Google. Дневной бюджет приложения сбрасывается в 00:00 UTC;
это не обещание такого же сброса квот Google.

## Ошибки и восстановление

Для своих лимитов возвращаются RATE_LIMITED/DAILY_LIMIT и retryAfterSeconds.
Перехваченная ошибка квоты → QUOTA_EXCEEDED без выдуманного времени восстановления.
Ошибка до запуска обработчика → failure/таймаут; если сама HTML-страница не загрузилась,
Google может показать свою ошибку. Гарантировать собственную страницу в таком случае нельзя.
Запретить бесконечные повторы и polling; проверка только по явному действию пользователя.

Если сервис нестабилен: выключить SERVICE_ENABLED, посмотреть Apps Script Executions и
ошибки квот, дождаться восстановления, проверить диагностический RPC и только затем включить.
Не логировать запросы целиком. Не удалять бюджет ради обхода ограничений Google.
Изменения лимитов требуют проверки количества обращений к Properties/Sheets на одну операцию.
